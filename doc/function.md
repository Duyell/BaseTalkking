# 交流基地 — 邀请制论坛系统需求规格说明书

## 1 项目概述

### 1.1 项目背景

传统开放式论坛存在用户杂乱、垃圾信息泛滥、恶意刷屏、低质内容扎堆等问题，难以维护社区氛围与内容质量。为打造小众、优质、私密的交流社区，本次基于 **Go + React 技术栈**开发**邀请制专属论坛系统**，摒弃开放式注册模式，仅通过专属邀请码完成用户入驻，严格把控用户准入门槛，保障社区纯净性与交流质量。

### 1.2 项目目标

开发一套轻量化、高安全、易扩展的邀请制论坛系统，实现核心的邀请码准入、用户管理、帖子发布、评论互动、后台权限管控等功能。系统主打私密小众社区属性，适配个人实战项目、小型私密社群使用，支持后续功能迭代扩展，运行稳定、操作简洁、安全性高。

### 1.3 技术栈

| 层级 | 技术选型 |
|------|----------|
| **后端** | Go 1.19+, MySQL 8.0+ ，Gin 框架 ,Redis 7.0+ ,JWT |
| **前端** | React 18+, TypeScript, Vite, React Router, Axios |
| **部署** | Nginx 反代前端静态资源 + 后端 API 代理, Docker  |
| **环境** | 云轻量应用服务器 (Linux), 客户端为主流浏览器 |

## 2 整体功能概述

本系统核心特色为**纯邀请制注册**，无公开注册入口，所有用户必须通过有效邀请码方可完成入驻。系统整体分为两大模块：前台用户模块、后台管理员模块，核心业务围绕邀请码体系、社区内容互动、权限管控展开。

核心能力：严格的邀请准入机制、轻量化社区内容互动、分级权限管理、内容审核管控、邀请码全生命周期管理。

## 3 功能性需求

### 3.1 邀请码核心模块（系统核心特色）

邀请码为用户入驻论坛的唯一凭证，所有注册行为必须绑定有效邀请码，无邀请码无法注册账号。

- **邀请码生成**：仅管理员在后台拥有生成权限，支持批量生成、单个生成；邀请码采用 16 位随机字符（字母+数字），基于雪花算法或 UUID 生成唯一编码，杜绝重复。
- **邀请码属性配置**：生成时可设置有效期（永久/自定义时间）、使用次数（默认单次有效，不可复用），支持手动启用/禁用指定邀请码。
- **邀请码状态管理**：状态分为`未使用`、`已使用`、`已过期`、`已禁用`四种；系统自动校验过期时间，超时自动失效，无法用于注册。
- **邀请码溯源记录**：全程记录邀请码创建时间、创建管理员、使用用户、使用时间，实现全生命周期溯源。

### 3.2 用户模块

#### 3.2.1 用户注册

- 系统关闭公开注册通道，用户必须填写**有效未使用、未过期、未禁用**的邀请码，搭配用户名、密码方可完成注册。
- 单个邀请码仅支持绑定一个账号，注册成功后邀请码自动标记为已使用。
- 注册时密码需加密传输（前端哈希/后端加密存储），密码强度需校验（长度 ≥ 8 位，包含字母+数字）。

#### 3.2.2 用户登录

- 支持**账号密码登录**，登录成功后生成 JWT Token，前端存储于 localStorage 或 httpOnly Cookie，保留登录状态。
- 支持**验证码登录**（可选拓展），通过绑定邮箱接收验证码。
- 校验账号状态，封禁用户无法登录，提示账号异常信息。

#### 3.2.3 个人中心

- 用户可查看、修改个人昵称、头像、简介等基础资料。
- 可查看个人发布的所有帖子、评论。
- 可查看自身账号状态、注册来源邀请码信息。

#### 3.2.4 用户权限分级

系统分为两种角色权限，严格区分操作范围：

- **普通用户**：登录浏览帖子、发布帖子、发表评论、编辑个人资料，无邀请码生成、用户管理、内容审核权限。
- **管理员**：拥有所有权限，可管理邀请码、管理所有用户、审核/删除帖子、封禁用户、管控社区内容。

### 3.3 论坛内容模块

#### 3.3.1 帖子功能

- **帖子发布**：登录用户可发布帖子，填写标题、正文内容，支持基础文本编辑。
- **帖子展示**：前台展示帖子列表，按发布时间倒序排序，展示标题、发布用户、发布时间、简短内容预览。
- **帖子操作**：用户可查看帖子详情、编辑/删除自己发布的帖子；管理员可删除任意违规帖子、置顶优质帖子。
- **内容过滤**：后端自动转义用户输入的特殊字符，防御 XSS 脚本注入，屏蔽恶意违规内容。

#### 3.3.2 评论功能

- 登录用户可在帖子下方发表评论，支持纯文本评论。
- 用户可删除自己的评论，管理员可删除所有违规评论。
- 评论按发布时间正序展示，关联对应帖子与发布用户。

### 3.4 后台管理模块

#### 3.4.1 邀请码管理

管理员可查看所有邀请码列表，包含编码、状态、有效期、创建时间、使用记录；支持新增、禁用、删除过期/无效邀请码，批量清理失效数据。

#### 3.4.2 用户管理

管理员可查看所有注册用户列表，查看用户基础信息、注册时间、发帖数量；支持用户禁言、账号封禁、解除封禁操作，清理违规用户。

#### 3.4.3 内容管理

管理员可查看全站所有帖子、评论内容，对违规内容进行删除、下架处理；可置顶优质帖子，维护社区内容质量。

## 4 非功能性需求

### 4.1 安全性需求

- 账号密码加密存储（BCrypt/SCrypt），禁止明文保存。
- 严格权限拦截，前后台权限隔离，普通用户无法访问后台管理接口与页面。
- JWT Token 设置合理过期时间（建议 7 天），支持 Token 刷新机制。
- 邀请码防暴力破解，采用长随机编码，无规律可破解。
- 前端、后端双重过滤用户输入，防御 XSS 攻击、SQL 注入。
- API 接口添加速率限制（Rate Limiting），防止恶意高频请求。
- 前后端通信强制 HTTPS（Nginx 层配置 SSL）。

### 4.2 性能需求

- 页面响应时间 ≤ 1 秒，接口请求响应时间 ≤ 500ms。
- 支持百人级同时在线访问，满足小型私密社区使用需求。
- 数据库查询高效，合理建立索引，基础查询无卡顿。
- 前端静态资源打包后启用 Nginx 缓存与 Gzip 压缩。

### 4.3 可扩展性需求

- 代码结构分层清晰，模块化开发，低耦合高内聚。
- 后端采用 Controller → Service → Mapper 三层架构，前端采用组件化开发。
- 支持后续拓展点赞、收藏、板块分类、消息通知、图片上传等功能。
- 数据库表结构预留扩展字段（如 `ext_json`），适配后续业务升级。

### 4.4 易用性需求

- 前台页面简洁直观，操作流程简单，新手用户可快速上手。
- 后台管理界面功能分区清晰，管理操作便捷高效。
- 系统操作异常均有明确提示信息（前端 Toast 提示 + 后端统一异常处理）。
- 前端响应式适配 PC 端与移动端显示。

## 5 前端详细规格

### 5.1 页面路由结构

| 路由 | 页面 | 权限 |
|------|------|------|
| `/login` | 登录页 | 公开 |
| `/register` | 注册页（需邀请码） | 公开 |
| `/` | 首页-帖子列表 | 登录用户 |
| `/post/:id` | 帖子详情 | 登录用户 |
| `/post/create` | 发布帖子 | 登录用户 |
| `/post/:id/edit` | 编辑帖子 | 帖子作者 |
| `/profile` | 个人中心 | 登录用户 |
| `/profile/edit` | 编辑资料 | 登录用户 |
| `/admin` | 后台管理首页 | 管理员 |
| `/admin/invite` | 邀请码管理 | 管理员 |
| `/admin/users` | 用户管理 | 管理员 |
| `/admin/posts` | 内容管理 | 管理员 |

### 5.2 前端技术要点

- **状态管理**：使用 React Context 或 Zustand 管理全局登录状态与用户信息。
- **请求封装**：基于 Axios 封装请求层，统一添加 JWT Token、错误拦截（401 跳转登录）、请求/响应日志。
- **路由守卫**：React Router 的 loader/guard 机制实现权限控制，未登录用户强制跳转登录页，非管理员无法访问后台路由。
- **UI 框架**：推荐使用轻量级 UI 库（如 Ant Design、Mantine 或 Tailwind CSS），兼顾开发效率与视觉效果。
- **构建优化**：Vite 构建，代码分割（lazy load）、静态资源哈希、生产环境启用 Gzip/Brotli 压缩。

## 8 部署方案

### 8.1 部署架构

```
用户 → Nginx (443 HTTPS) → /api/* 反代 → Go 后端 (:8080)
                         → /* 静态资源   → React 前端 (dist/)
```

### 8.2 Nginx 配置要点

- 监听 443 端口，配置 SSL 证书，强制 HTTPS 跳转。
- 前端路由使用 `try_files $uri /index.html` 实现 SPA 单页应用路由支持。
- `/api/` 路径反向代理到后端 Java 服务，携带原始请求头（Host、X-Real-IP、X-Forwarded-For）。
- 静态资源启用强缓存（`Cache-Control: max-age=31536000, immutable`），HTML 文件禁用缓存。
- 启用 Gzip 压缩，提升静态资源加载速度。
- 配置合理的请求体大小上限（`client_max_body_size`，如图片上传需要调整）。

### 8.3 服务端环境

| 组件 | 版本/说明 |
|------|-----------|
| 操作系统 | Linux (Ubuntu 22.04 / CentOS 7+) |
| Go | 1.19+ |
| MySQL | 8.0+ |
| Redis | 7.0+ |
| Nginx | 1.24+ |
| Node.js | 用于构建前端（生产环境可只需 dist 产物） |
| Docker | 可选，用于容器化部署 |

### 8.4 部署流程

1. **构建前端**：`npm run build` 生成 `dist/` 静态目录。
2. **构建后端**：`CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o base-talkking .` 交叉编译为 Linux 可执行文件。
3. **配置 Nginx**：编写 nginx.conf，配置 SSL、静态资源路径、API 反代。
4. **上传服务器**：将 dist 目录、Go 可执行文件、配置文件、nginx.conf 上传至服务器。
5. **启动后端**：`./base-talkking -env prod` 启动 Go 服务（支持 systemd 或 supervisor 守护进程管理）。
6. **启动 Nginx**：`nginx -s reload` 加载配置。
7. **验证**：访问域名验证前后端功能正常。

### 8.5 环境配置文件

后端使用 Viper 管理配置，支持 YAML/TOML/JSON 格式，按环境加载不同配置文件：

- **开发环境** (`config.dev.yaml`)：本地 MySQL/Redis 连接，debug 日志级别，CORS 允许本地前端端口（localhost:5173）。
- **生产环境** (`config.prod.yaml`)：生产 MySQL/Redis 连接，info 日志级别，关闭 debug，CORS 交由 Nginx 处理。

## 9 业务流程说明

### 9.1 用户注册流程

管理员生成邀请码并下发 → 用户获取有效邀请码 → 进入注册页面填写账号、密码、邀请码 → 系统校验邀请码有效性 → 校验通过完成注册 → 邀请码标记为已使用 → 账号创建成功。

### 9.2 帖子发布与互动流程

用户登录账号 → 发布帖子 → 系统过滤恶意内容并保存 → 前台展示帖子 → 其他用户浏览、评论 → 用户/管理员可管理对应帖子、评论内容。

### 9.3 邀请码管理流程

管理员登录后台 → 生成/配置邀请码 → 查看邀请码使用状态 → 对过期、失效、违规邀请码进行禁用、删除处理 → 全程溯源使用记录。

## 10 约束与边界说明

- 系统**无公开注册功能**，所有新用户入驻必须依赖有效邀请码，无任何例外渠道。
- 邀请码默认单次有效，使用后立即失效，不支持重复复用。
- 普通用户无任何后台管理权限，无法操作邀请码、用户、全站内容。
- 所有用户输入内容必须经过安全过滤，杜绝恶意代码注入。
- 仅管理员可进行帖子置顶、用户封禁、内容删除等管控操作。
